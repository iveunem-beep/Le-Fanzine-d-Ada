L'édito

Cette semaine, quelque chose bascule. On ferme l'onglet du navigateur et on ouvre un terminal, et le même langage qu'on écrivait hier pour faire clignoter un bouton se met soudain à lire des fichiers, à écrire des dossiers, à parler à la machine directement.

Pendant cinq semaines, le JavaScript vivait dans une page. Il attendait qu'on clique. Il changeait des couleurs. Il était utile, mais il était enfermé. À partir de maintenant, il sort.

C'est un moment étrange dans une formation. On ne rajoute pas une brique au-dessus des autres : on déplace le sol. Et pour la première fois, on écrit du code qui ne se voit pas.

J'ai passé une heure à chercher pourquoi ma page ne s'affichait pas. Il n'y avait pas de page. C'était un script.

Protocole de survie

Ce qu'il faut faire, dans l'ordre, quand un script Node refuse de démarrer.

  1. Lire le message d'erreur en entier. Vraiment en entier, jusqu'à la dernière ligne.
  2. Vérifier qu'on est dans le bon dossier avec pwd.
  3. Vérifier que le fichier existe avec ls.
  4. Relire le nom du fichier caractère par caractère.
  5. Respirer, puis demander à quelqu'une de regarder par-dessus l'épaule.

Une erreur MODULE_NOT_FOUND ne parle presque jamais d'un module manquant. Elle parle d'un chemin qui ne mène nulle part.

Le module fs écrit vraiment sur le disque. Il n'y a pas de bouton « annuler », pas de rechargement de page qui remet tout à zéro.
